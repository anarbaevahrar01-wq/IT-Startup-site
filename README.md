# QR DINE — QR-меню и онлайн-заказы для кафе

> **Scan • Order • Enjoy** — гость сканирует QR-код на столе, выбирает блюда и делает заказ,
> а кафе принимает его в админ-панели в реальном времени.

## Стек

| Слой | Технология | Почему |
|---|---|---|
| Сервер | **Node.js 22+**, **Express 5** | async-ошибки обрабатываются сами, ESM, `--watch`, `--env-file` без пакетов |
| Интерактив | **htmx 2** | сервер возвращает HTML-фрагменты, SPA-фреймворк и сборщик не нужны |
| Шаблоны | **Nunjucks** | наследование layout'ов, макросы, автоэкранирование (XSS) |
| База данных | **SQLite** через встроенный `node:sqlite` | нет нативных зависимостей, один файл, миграции в SQL |
| Валидация | **zod** | декларативные схемы форм, сообщения на казахском |
| Безопасность | helmet (CSP), проверка Origin (CSRF), scrypt, SameSite-cookie | |
| Шрифты | Inter + Montserrat (Fontsource, локально) | без внешних CDN |

## Быстрый старт

```bash
npm install
cp .env.example .env     # Windows: copy .env.example .env
npm run brand            # сгенерировать SVG/PNG логотипа и иконок
npm run dev              # http://localhost:3000
```

При первом запуске автоматически создаются база, администратор и демо-кафе **Volidam** (30 позиций, 6 столов).

| | |
|---|---|
| Сайт | http://localhost:3000 |
| Админ-панель | http://localhost:3000/admin |
| Логин / пароль админа | `admin@qrdine.kz` / `admin12345` (меняется в `.env`) |
| QR-вход за стол №3 | http://localhost:3000/t/volidam/3 |

> **OneDrive.** Если папка проекта синхронизируется OneDrive, режим `npm run dev` (`node --watch`)
> может сам перезапускаться из-за служебных изменений файлов. В таком случае используйте `npm start`
> или перенесите проект в папку вне OneDrive (например, `C:\Projects\QRDine`).

> Чтобы проверить QR-коды с телефона, укажите в `.env` `BASE_URL=http://<IP-компьютера>:3000`.

## Возможности

**Для гостя**
- Главная: hero, «как это работает», список кафе, блок для бизнеса.
- Страница кафе: меню по категориям, **живой поиск** (htmx), добавление в корзину без перезагрузки.
- QR-код стола (`/t/<кафе>/<номер>`) запоминает стол — при оформлении он уже выбран.
- Корзина с изменением количества, оформление заказа с валидацией.
- Страница заказа со **статусом в реальном времени** (опрос каждые 5 с, автоостановка по коду 286).
- Регистрация / вход, личный кабинет с историей заказов.
- Заявка от кафе на подключение.

**Админ-панель** (`/admin`)
- Дашборд: выручка за сегодня, активные заказы, средний чек, график за 7 дней, топ блюд, живая лента заказов.
- Заказы: фильтры по статусу/кафе/поиску, смена статуса прямо в таблице, автообновление каждые 10 с, карточка заказа.
- Меню: категории, CRUD блюд с загрузкой фото, переключатель «в меню».
- Кафе: CRUD, обложка, столы, **скачивание QR-кода** каждого стола и **страница печати** тейбл-тентов.
- Заявки от кафе и пользователи (смена роли, удаление).

### Слои внутри модуля

```
routes  →  service (бизнес-правила)  →  repository (только SQL)  →  SQLite
   ↓
views (Nunjucks) — полная страница или фрагмент для htmx
```

### Как устроен htmx в проекте

- `hx-boost` на `<body>`: все ссылки и формы работают как SPA-переходы, но остаются обычным HTML.
- Действия, меняющие часть страницы, отвечают **фрагментом** из `views/fragments` или `views/admin/**/_*.njk`.
- Несколько мест обновляются одним ответом через `hx-swap-oob` (счётчик корзины, панель, уведомление).
- Ошибки валидации — статус **422**, htmx настроен вставлять такие ответы (`<meta name="htmx-config">`).
- Inline-JS запрещён CSP — всё поведение в `public/js/app.js` через делегирование событий.

## Вход через Google

Регистрация и вход через Google-аккаунт работают по OAuth 2.0 (Authorization Code + PKCE)
без сторонних библиотек — см. `src/modules/auth/google.service.js` и `google.routes.js`.

- Новый пользователь Google → создаётся аккаунт (регистрация).
- Email уже зарегистрирован паролем → Google-аккаунт привязывается к нему
  (принимаются только email, подтверждённые Google).
- Без ключей `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` кнопка просто не показывается.

**Как получить ключи:**

1. [Google Cloud Console](https://console.cloud.google.com/) → создайте проект.
2. **APIs & Services → OAuth consent screen**: тип *External*, название «QR DINE», email поддержки.
3. **APIs & Services → Credentials → Create credentials → OAuth client ID**, тип *Web application*.
4. **Authorized redirect URIs**:
   - `http://localhost:3000/auth/google/callback` — для разработки;
   - `https://it-startup-site-1.onrender.com/auth/google/callback` — для сайта на Render.
5. Скопируйте *Client ID* и *Client secret* в `.env` (локально) и в **Environment** на Render.

Адрес возврата строится из `BASE_URL`, поэтому он должен совпадать с адресом в Google Console.

## Логотип и иконки

Логотип нарисован векторно в `src/lib/brand.js` (буквы — контуры, не шрифт).
`npm run brand` создаёт:

- `public/img/brand/logo.svg`, `logo-dark.svg`, `logo-compact.svg`, `mark.svg`
- `public/favicon.svg`, `public/icons/*.png` (32, 180, 192, 512, maskable, og-image 1200×630)

На страницах логотип вставляется инлайном, его цвета управляются CSS-переменными `--logo-*`.

## Production

```bash
NODE_ENV=production SESSION_SECRET=<длинная-строка> ADMIN_PASSWORD=<пароль> BASE_URL=https://example.kz npm start
```

Папку `storage/` нужно хранить на постоянном диске (там база и загруженные фото).
